# PRD: 伴语 (Banyu)

> 主动式 AI 陪伴产品。一个有性格的虚拟角色，会主动来找你聊，提供情绪支持。内置默认角色，支持自定义角色卡。

---

## 1. 需求清单

### 1.1 流式聊天对话 [P0]
- **功能描述**：用户与角色实时对话，LLM 流式输出回复，消息历史持久化
- **验收标准**：
  - 成功路径：用户发送消息 → 后端流式调用 LLM → SSE 逐 token 推送前端 → 打字效果渲染 → 消息落库
  - 失败路径：LLM 调用失败 → 显示"角色暂时走神了，稍后再试" → 用户消息不丢失；网络中断 → 提示重连
  - 边界条件：空消息不发送；超长消息(>4000 字)截断并提示；并发消息排队
  - 性能：首 token <1.5s，完整回复 <30s
- **优先级**：P0

### 1.2 主动式陪伴 [P0]
- **功能描述**：角色定时主动发消息（早安/晚安/随机问候）+ 事件触发（久未上线/情绪低落）主动关心，通过 Web Push 推送
- **验收标准**：
  - 成功路径：定时任务触发 → 生成主动消息 → Web Push 推送 + 应用内消息；用户点击推送 → 打开对话页 → 看到角色主动消息
  - 失败路径：推送服务不可达 → 消息存应用内待用户上线展示；LLM 生成失败 → 使用预设兜底文案
  - 边界条件：用户关闭通知 → 仅应用内展示；夜间时段(23:00-7:00)不推送（除非用户开启）；同日主动消息 ≤3 条
  - 定时任务准时触发（误差 <1min）
- **优先级**：P0

### 1.3 角色系统 [P0]
- **功能描述**：内置默认角色 + 用户自定义角色卡（人设/头像/声音/触发配置）
- **验收标准**：
  - 成功路径：用户创建角色卡 → 填写人设/头像/声音/主动触发配置 → 保存 → 切换到该角色对话
  - 失败路径：人设为空 → 阻止保存并提示；图片上传失败 → 使用默认头像
  - 边界条件：角色卡数量上限 20；人设文本 ≤2000 字；支持编辑/删除/复制
  - 人设一致性：对话不崩人设
- **优先级**：P0

### 1.4 长期记忆 [P0]
- **功能描述**：pgvector 检索用户关键信息注入对话上下文，角色能记住用户的事
- **验收标准**：
  - 成功路径：用户提及关键信息（姓名/喜好/事件）→ 提取存储为向量记忆 → 后续对话检索 top-k 相关记忆注入 system prompt → 角色复述/引用
  - 失败路径：向量库查询失败 → 降级无记忆对话，不阻断
  - 边界条件：记忆检索 top-5；记忆去重；用户可查看/删除记忆
  - 验收：角色能复述 3 天前用户提及的事
- **优先级**：P0

### 1.5 语音对话 [P1]
- **功能描述**：Web Speech API 语音输入(ASR) + 角色语音输出(TTS)
- **验收标准**：
  - 成功路径：用户点击语音按钮 → ASR 识别 → 填入输入框 → 发送 → 角色回复 → TTS 播放语音
  - 失败路径：ASR 识别失败 → 提示"没听清，再说一次"；TTS 不可用 → 仅文字显示
  - 边界条件：浏览器不支持 Web Speech → 隐藏语音按钮；语音输入 ≤60s
- **优先级**：P1

### 1.6 心情日记 [P1]
- **功能描述**：用户记录每天心情/小事，角色基于日记主动陪伴
- **验收标准**：
  - 成功路径：用户写日记 → 保存 → 提取关键信息入记忆 → 角色下次对话/主动消息引用日记内容
  - 失败路径：保存失败 → 提示重试，不丢内容
  - 边界条件：日记 ≤1000 字；支持查看历史日记；日记可设私密
- **优先级**：P1

### 1.7 情绪识别触发 [P1]
- **功能描述**：LLM 分析用户消息情绪，负面情绪触发角色主动关心
- **验收标准**：
  - 成功路径：用户消息 → 情绪分析(负面得分 >阈值) → 触发角色主动关心消息 → 推送/应用内
  - 失败路径：情绪分析失败 → 跳过不阻断对话
  - 边界条件：避免重复触发（同会话 ≤1 次主动关心）；阈值可调；正面情绪不触发
- **优先级**：P1

## 2. 视觉/页面框架
- **参考网站**：1. 星野 2. Replika 3. 豆包（Pi 被 Cloudflare 拦截，改用豆包补充对话 UI）
- **参考截图**：
  - `references/design/reference/xingye-home-*.png` - 星野首页（角色卡/氛围）
  - `references/design/reference/replika-home-*.png` - Replika 首页（治愈气质/主动文案）
  - `references/design/reference/doubao-chat-*.png` - 豆包对话页（对话布局）
- **设计要素提取**：
  - 星野：暗色底+暖金强调、二次元 ACG 氛围、角色卡横向轮播、顶部极简导航、星点装饰
  - Replika：浅蓝白底+橙色强调、温暖治愈生活化、主动消息文案（"thought of you today"）、记忆/关系/成长卖点
  - 豆包：浅白灰底+亮蓝强调、简约工具风、左侧栏+主对话区二分布局、圆角气泡+大圆角输入框
- **风格方向**：温暖、疗愈、情绪支持向。综合 Replika 温暖治愈气质 + 豆包清爽对话布局。配色取浅色温暖底（米白/浅暖灰）+ 暖色强调（暖橙/暖粉），不用星野暗黑二次元（与情绪支持调性冲突）
- **导航结构**：移动端底部 tab（对话 / 角色 / 日记 / 我的）+ 对话页全屏沉浸；桌面端参考豆包左侧栏布局
- **页面布局**：
  - 对话页：消息流（圆角气泡式）+ 底部输入栏（大圆角，文字/语音切换）+ 顶部角色信息
  - 角色卡管理页：角色列表（卡片，参考星野描边圆角卡）+ 创建/编辑表单
  - 日记页：日历 + 今日日记编辑 + 历史列表
  - 设置页：API key 配置 / 模型选择 / 通知开关 / 记忆管理
- **主动消息文案风格**：参考 Replika，短句、生活化、像真朋友（如"今天想到你了，没别的事"）
- **避免 AI 味**：✓（不使用"智能/赋能/助力/驱动/生态"）

## 3. 项目边界
- [x] **上线公开**（做能用的产品，面向用户）
- [x] **用户数据**：账号 / 对话 / 日记 / API key → 需隐私合规；MVP 无支付
- [x] **性能与成本**：首 token <1.5s，回复 <30s；用户自带 LLM API key，运营成本低

## 4. 技术栈（架构锁定，详见 02-ARCHITECTURE.md）
| 层 | 选型 |
|----|------|
| 前端 | Next.js 14 (App Router) + TS + Tailwind + shadcn/ui + Zustand + PWA |
| 后端 | FastAPI (Python) |
| LLM | 多 Provider 适配层（OpenAI/豆包/通义/DeepSeek/智谱/Gemini），用户配 API key，`/models` 返回可用模型 |
| 语音 | Web Speech API (MVP) |
| 数据库 | Postgres + pgvector |
| 主动陪伴 | APScheduler 定时 + 上线/情绪事件 + Web Push |
| 打包 | Capacitor(移动) + Tauri(桌面) |
| 部署 | Vercel(web) + 云服务器(FastAPI) + Neon/Supabase(PG) |
